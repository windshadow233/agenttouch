# 板子独立 RSS 播客

板子直接通过 Wi-Fi 读取 RSS 和 MP3，不经过 Mac 下载或转码，不把整集写入 SD 卡。Mac 仅用于第一次配置 RSS；配置保存在板子 NVS，之后可关闭 Mac 后台、断开蓝牙，独立刷新和播放。

## 首次设置

1. 更新并烧录固件，更新 Mac 后台，打开本机设置页「听什么」。
2. 在「板子独立联网播客」中输入 RSS，例如 `https://feeds.daopub.com/ld.xml`，点击「保存」，再在顶部将播放模式切到「网络 RSS」。配置时板子通过蓝牙或 TCP 连接 Mac 即可。
3. 板子连接可访问互联网的 2.4 GHz Wi-Fi。首次 HTTPS 连接需要正确的系统 UTC 时间：连接 Mac 时自动同步，并保存时区偏移；之后独立启动可从有效 RTC 恢复 UTC，缺少可信时间时再通过 NTP 校时。
4. 切到原有播客页，点底部「获取节目」更新 RSS，再点「列表」选择单集。

## 板子操作

- 原有播放界面保留：中间播放/暂停；左右短按近似后退/前进 15 秒；长按约 0.7 秒切换上一集/下一集，首尾循环。
- 按住进度条上的圆点或进度条附近左右拖动，预览目标时间，松手后跳转；也可直接点选进度位置。暂停时跳转仍保持暂停，拖动不会切换页面或调节音量。只有节目提供总时长时才能拖动。RSS MP3 按码率估算位置，VBR 节目可能不精确，且音频服务器需要支持 HTTP Range；首次跳转会先读取 MP3 帧以确定码率，再定位并缓冲。
- 「获取节目」：在后台重新获取 RSS，按 RSS 提供顺序解析所有单集，不设置保存集数上限，不停止当前播放。刷新完成后保持当前单集、播放状态和进度；刷新失败时保留原列表，仍可暂停、跳转和切集。获取期间按钮变为「取消」，点击可中止本次下载或解析并保留原列表、当前选集和播放进度；取消后按钮恢复「获取节目」，可重新开始。后台若正在等待 DNS/TLS/HTTP 返回，会在该调用返回后结束，不再重试。有 SD 卡时先下载完整 RSS，再从卡上循环读取解析；状态行先显示「下载 N KB · 0 集」，随后显示「解析 N KB · M 集」，分别显示下载量和解析集数；断线重试保留已下载字节和解析状态，不自动从零重新获取，成功后显示「最近 N 集 · 新增 M 集」（英文 `Latest N / New M`，按音频链接与原列表去重比较）5 秒，再恢复节目状态。
- 「列表」：每页 4 集，点击选集；左右下方按钮或上下滑翻页；选完返回原播放页。点击顶部页码打开数字键盘，输入目标页后点「跳转」；「删除」可退格，「取消」返回列表。每次打开列表自动定位到当前单集所在页。
- 进度条灰色部分表示当前位置之后已解码、可直接播放的缓冲范围；已播放部分保持强调色。拖动预览期间不显示旧位置的缓冲范围。
- 开始时预缓冲约 8 秒的音频数据，最多保留约 30 秒 PCM，接收、解码和播放并行。缓冲用 RAM，不是下载整集。网络抖动导致缓冲耗尽时会重新缓冲，恢复门槛逐次增加 2 秒，最多 16 秒，减少反复停播。MP3 缓冲仍有完整帧时优先解码，不为补充网络数据阻塞输出。
- RSS 默认通过一个 HTTP 响应连续下载到 SD 卡 `/agentpet/rss-download.tmp`，下载完整后使用 C++ 循环读取文件解析，成功后保留为 `/agentpet/rss.xml`。下载将 TLS 小块数据合并为 16 KB SD 写入，缓冲放在 PSRAM；写入完成后关闭文件并以只读方式重新打开，SD 读回使用预留的内部 DMA 缓冲，不在 RAM 中加载整份 XML。每解析 16 集就把元数据写入 `/agentpet/rss-items.tmp` 并清空解析批次，结束后生成最终 PSRAM 列表；标题和链接使用 PSRAM 分配器，合并时移动新列表，避免额外复制整份列表；单份 RSS 仍有 4 MB 的文件大小保护。无 SD 卡时沿用边下载边解析。不再每 64 KB 主动分段请求或重复建立 HTTPS 连接。连接提前结束时，RSS 和音频会在服务器提供版本标识并支持 Range 的情况下，从已接收位置续传；自动重试保留同一个临时文件及下载偏移，Wi-Fi 断开时先等待最多 30 秒恢复。续传校验响应范围、总长度和版本标识，防止重复或拼接不同版本；连续恢复失败才显示错误；服务端缺少续传所需的版本标识、忽略 Range 或文件已变化时，明确报错并保留原列表，用户可点击「获取节目」重新开始。临时文件用于本次获取期间续传，重启或重新点击获取会从头下载。
- 断网或解码失败会在状态行显示错误；恢复网络后点播放重试或刷新列表。较长时间暂停可能使远端连接过期，需要重新播放。

## 支持范围

- UTF-8 RSS 2.0 的 `<item><enclosure url="…" type="audio/mpeg"/>`。支持 HTTP、HTTPS 和重定向，保留 TLS 证书验证。
- 当前解码 MP3；明确标为其他音频格式的条目不会进入列表。不支持 Atom、AAC/M4A、HLS、DRM 或需要登录的音源。
- 跳转需服务端支持 HTTP Range，基于码率估计定位，VBR 音源可能不精确；不支持分段读取时会提示错误。
- 无需 SD 卡存储音频；完整中文标题的字库仍沿用项目原有方式，缺字时可能需要卡上的完整字库。
- 检测到 SD 卡时，将当前 RSS 的单集元数据保存到卡上，不设置保存条数上限（实际容量受可用内存和 SD 空间限制）。重启后优先加载卡上的列表，不必先刷新 RSS；上次收听的单集和进度保存在 NVS，重启后自动恢复选集和进度，保持暂停，点击播放即可继续。刷新按直链去重，新列表优先，保留旧条目，不因条数增加而淘汰。只保存标题、音频链接和时长，不下载整集音频，播放仍需 Wi-Fi；直链过期时需要重新刷新。
- 列表保存在 SD 卡的 `/agentpet/rss-a.json` 和 `/agentpet/rss-b.json`，双槽交替写入；一份损坏时尝试恢复另一份，相同列表不重复写入。没有 SD 卡时仍能刷新和播放，但列表只保留在内存，重启后需先联网重新获取列表，再恢复上次单集。之后插入 SD 卡会保存当前列表，无需重新获取。缓存不使用或格式化板子 Flash，也不格式化 SD 卡。`/radio/status` 的 `cache_storage` 表示是否检测到 SD 卡，写入失败时查看 `cache_error`。
- 收听期间每 15 秒保存一次进度，暂停或切集时立即保存；突然断电最多丢失约 15 秒进度。保留最近 100 集的进度记录，单集列表本身不设条数上限。
- 网页顶部的「离线模式」可切回原有播放器，不删除任何已下载节目。

## 编译和测试

`pio run -e amoled216` 编译，`pio run -e amoled216 -t upload` USB 烧录。
MP3 解码器来自 dr_libs/dr_mp3，固定源码提交见 `THIRD_PARTY_LICENSES/dr_mp3.txt`。未新增在线包依赖。

板上验证应包括：Mac 后台关闭后的 RSS 刷新和播放；至少 30 分钟播放及缓冲；断网恢复；暂停继续；短按跳转、长按切集和首尾循环；再检查现有蓝牙听写、批准和本地 SD 播放。


## TLS 内存

为避免内部 RAM 不足导致 `tls=-32512 SSL - Memory allocation failed`，mbedTLS 工作区（包括小块分配）优先使用 PSRAM，硬件 AES/DMA 所需内存仍使用内部 RAM；保留 SDK 释放函数和 TLS 证书校验。`/radio/status` 的 `tls_psram`、`internal_free` 和 `internal_largest` 可确认新固件特性及内部堆状态。

RSS 与 MP3 工作线程保留在内部栈（lwIP 的 TCP 建连要求），TLS 工作区和解码缓冲优先放 PSRAM，为 TLS/AES 硬件解密预留内部内存；HTTP 流失效时先检查并重连，避免连接中断后解引用空指针。`/radio/status` 的 `system_utc`、`clock_ready`、`tls_all_psram`、`rss_received`、`rss_requests`、`rss_download_ms`（含 SD 写入）、`rss_parse_ms`（含 SD 读回）、`rss_parsed` 和 `rss_http_status` 可用于诊断校时与实际获取进度。
